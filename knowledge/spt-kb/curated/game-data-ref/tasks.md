## 3. 奖励结构（TaskRewards）

奖励挂载于 `startRewards`（接取奖励）/ `finishRewards`（完成奖励）/ `failureOutcome`（失败结算）三个槽位，各槽位结构相同（10 种键）。

### 3.1 TaskRewards 类型分布

| 奖励类型 | 涉及任务数（start/finish/failure 任一） | start | finish | failure |
| --- | --- | --- | --- | --- |
| `traderStanding` | 360 | 0 | 359 | 1 |
| `items` | 541 | 65 | 476 | 0 |
| `offerUnlock` | 151 | 10 | 141 | 0 |
| `skillLevelReward` | 46 | 0 | 46 | 0 |
| `traderUnlock` | 2 | 0 | 2 | 0 |
| `craftUnlock` | 36 | 8 | 28 | 0 |
| `achievement` | 4 | 0 | 4 | 0 |
| `customization` | 12 | 1 | 11 | 0 |
| `traderDialogueUnlock` | 1 | 0 | 1 | 0 |
| `locationUnlock` | 0 | 0 | 0 | 0 |

### 3.2 字段说明与示例

#### `traderStanding`

- **字段**：商人声望：`{standing 数值, trader 商人id}`。
- **示例**：```json
{ "standing": 0.1, "trader": "54cb57776803fa99248b456e" }
```

#### `items`

- **字段**：物品奖励：`{item 物品id, count 数量, attributes 属性}`（attributes 多为空对象）。
- **示例**：```json
{ "item": "5449016a4bdc2d6f028b456f", "count": 80000, "attributes": {} }
```

#### `offerUnlock`

- **字段**：解锁商人报价/订购项：`{id, level 解锁等级, item 物品id, count, contains[], attributes[], trader 商人id}`。
- **示例**：```json
{ "id": "6a6fd12710725cfea532e56b", "level": 2, "item": "5c0e530286f7747fa1419862", "count": 1, "contains": [], "attributes": [], "trader": "54cb57776803fa99248b456e" }
```

#### `skillLevelReward`

- **字段**：技能等级奖励：`{skill 技能名, level 等级}`。
- **示例**：```json
{ "level": 2, "skill": "Surgery" }
```

#### `traderUnlock`

- **字段**：解锁商人（字符串：商人 id）。
- **示例**：```json
"6617beeaa9cfa777ca915b7c"
```

#### `craftUnlock`

- **字段**：解锁制作配方：`{level, station 工作站id, item 产物id, count}`。
- **示例**：```json
{ "level": 1, "station": "5d484fba654e7600691aadf7", "item": "55d482194bdc2d1d4e8b456b", "count": 1 }
```

#### `achievement`

- **字段**：成就奖励（字符串：成就 id）。
- **示例**：```json
"664f23e44702fd5db50ee732"
```

#### `customization`

- **字段**：外观解锁：`{id, name, imageLink, customizationType, customizationTypeName}`。
- **示例**：```json
{ "id": "67585d2cd7a2703986067e99", "name": "67585d2cd7a2703986067e99 Name", "imageLink": "https://assets.tarkov.dev/customization-67585d2cd7a2703986067e99.webp", "customizationType": "ShootingRangeMark", "customizationTypeName": "Hideout/Customization/ShootingRangeMark/TabName" }

#### `traderDialogueUnlock`

- **字段**：解锁商人对话（字符串：商人 id）。
- **示例**：```json
"5c0647fdd443bc2504c2d371"
```

#### `locationUnlock`

- **字段**：地点解锁（快照内无实例，键存在于奖励对象中但恒为空数组）。
- **示例**：无（快照内无实例）。


## 4. SPT 对照

SPT 4.1.2 的 `quests.json` 是任务体系的**运行时权威数据**；本节对照其与 live 快照的异同，供开发设计参考。

### 4.1 数量对照

| 数据源 | 任务数 |
| --- | --- |
| live 快照（tarkov.dev 2026-09-02） | **517** |
| SPT 4.1.2 quests.json | **558** |
| id 交集（同一 id 两侧均存在） | 463 |
| 仅 live | 54 |
| 仅 SPT | 95 |

> 说明：两侧共用同一套任务 id（live 目标 id 与 SPT condition id 可 1:1 对应）。SPT 4.1.2 锁定 0.16.9.5 时代任务表，保留了大量已被 live 1.1.0 移除或改造的任务（仅 SPT 95 个）；live 1.1.0 侧则有新增/重构任务（仅 live 54 个，含 ref 竞技场、taran/radio-station 等新商人任务）。

### 4.2 抽样结构对照（5 个已知任务）

| 任务（中文） | live id | live 目标（type 列表） | SPT AvailableForFinish（conditionType 扁平） | 目标 id 一致 | 差异要点 |
| --- | --- | --- | --- | --- | --- |

## 5. 使用建议

1. **权威性**：SPT 4.1 的 `quests.json`（`templates/quests.json`）是任务机制、条件、奖励的运行时事实来源，mod 开发以它为准。
2. **设计参考**：live 快照的任务结构（20 种目标类型、字段语义、奖励槽位）适合做 quest mod 的设计蓝图——特别是 1.0+ 新任务的紧凑表达方式（maps/zones 数组合并、targetNames 枚举、buildAttributes 属性阈值）。
3. **id 复用**：live 任务 id / 目标 id 与 SPT 同源，可直接作为对照锚点；但 1.0 时代部分任务已重编号（如惩罚者系列命名错位），跨版本匹配优先用 id 而非名称。
4. **差异预期**：live 1.0+ 任务链已移除大量 0.16 时代的 HandoverItem 阶段（并入目标本身）；SPT 侧 CounterCreator 包装（Kills/VisitPlace 内嵌）在 live 侧被扁平化为 type + count + 条件数组，二者语义等价、组织粒度不同。
5. **中文名**：中文名以 `tasks_zh.json` 为准（社区常用名可能不同，如 Debut 在本快照中为「首秀」而非「初来乍到」）。
