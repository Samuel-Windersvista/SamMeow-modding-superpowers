# GLOSSARY — LLM Trader Chat（SPT 4.1.6 线）

> 术语表（glossary）。只记录项目语言，不记录实现细节与规格。

## 核心术语

- **商人对话**：玩家在游戏内原生 Messenger 中与某个 SPT 商人（trader）之间的双向消息线程；
  本 mod 的目标载体——不做自建聊天面板，复用原生消息 UI 与发送链路。
- **检索后端适配口**：`IKnowledgeRetriever` 抽象——聊天引擎请求「与玩家问题相关的知识片段」的接口；
  v1 提供关键词/子串实现，嵌入向量检索等后端可在此接缝后替换。
- **开场消息**：某个商人首次启用可聊天时，由本 mod 主动发往该商人消息线程的一次性欢迎消息；
  除开场外商人只被动回复，不主动发消息。
- **聊天引擎**：`TraderChatEngine`——对话逻辑主接缝；编排 reset 指令识别、开场判定、检索、
  prompt 组装、LLM 调用与失败兜底；不依赖 SPT 具体实现（依赖接口注入）。
- **人格（persona）**：每个商人配置的语气设定（如 Peacekeeper 的美式承包商语气、Therapist 的冷静医生语气），
  参与 system prompt 组装。
- **知识文档**：`knowledge/traders/<traderId>/` 下供检索使用的 md/txt 文件；per-trader 配置的 `docsDir` 指向之。
- **试点商人**：v1 首批启用的原版商人——Peacekeeper 与 Therapist。
- **全商人接入批次（工单 13）**：把《永远的诺文斯克》内的商人人集（12 位原版 + 7 位 mod，共 19 位）
  全部登记进发布默认配置与客户端默认名单的扩展批次；后续新增商人仍走「最小接入契约」。
- **mod 商人**：由整合包内第三方 mod 新增的商人（非原版）；工单 08 以 Painter（油漆匠）验证其可经**纯配置**
  接入聊天，无需改代码或重编译。
- **最小接入契约**：新增一位商人所需的最小操作集合——服务端 `config.jsonc` 的 `traders[]` 追加一条、
  `knowledge/traders/<traderId>/` 放知识文档、客户端名单 JSON 加该 id；三处均为纯文本。
- **全局配置 / per-trader 配置**：前者统一 LLM 端点、延迟范围、历史条数、兜底话术等；后者按商人给出
  traderId、开关、人格、文档目录、开场消息与 reset 关键词。
- **兜底话术**：LLM 不可用或无有效回复时返回给玩家的一句提示，替代静默或报错刷屏。
- **独立联系人形态**：若「并入商人现有消息线程」不可行时的回退形态——为聊天单独建一个联系人
  （M1 骨架裁定采用哪种形态）。
- **动态态度（dynamic attitude）**：商人在对话中的语气冷暖与亲疏立场随玩家当前好感度、忠诚等级与任务合作进展而动态变化的机制；仅影响对话语气与谈资，不改变商人交易或任务逻辑，且不在对话中向玩家报出内部数值。
- **态度档位（attitude tier）**：将商人与玩家的关系划分为五个递进阶段——敌意/戒备（Hostile）、冷淡/生疏（Cold）、熟稔/认可（Familiar）、信任/器重（Trusted）、核心盟友/过命交情（Ally）。
- **玩家关系快照（relationship snapshot）**：单次生成回复前读取的玩家与目标商人关系状态（好感度、忠诚等级、解锁状态、该商人名下任务统计与近期任务名称、玩家阵营与等级），作为计算态度档位与组装上下文的输入。
- **任务知识（quest knowledge）**：商人在对话中可援引的、关于其名下委托的事实——委托名称、委托人视角的缘由、目标与地点线索。分两层：跟随玩家进度的当前委托详情，以及不随进度变化的委托常识。
- **披露档位（disclosure level）**：商人对委托细节的交代程度，三档——不披露（None）／只给方向性线索（Hint）／交底（Full）。由该商人与玩家的态度档位映射决定，是「低好感不说、高好感才交底」的机制化。
- **任务 FAQ**：每位有委托的商人的一份静态文档，承载不随玩家进度变化的委托常识与立场，用于补足对话中的任务问答。
