# ADR-0003：检索策略采用 v1 关键词实现 + 检索后端适配口

- 状态：已接受（2026-10-14）
- 决策人：Overseer（用户）

## 背景

要让商人回复基于玩家/服主给定的知识文档（涉及设定/FAQ 的问题能答对），需要一层检索增强。候选形态有三条：关键词/子串轻量检索；嵌入向量检索（本地 ONNX / Ollama / OpenAI embedding + 向量存储）；外部 RAG 服务。SPT 生态无现成 RAG 中间件，全部需自建（研究依据 `docs/research/llm-trader-chat-feasibility.md` §3.4）。

## 决策

v1 实现关键词/子串检索：支持 `.md` / `.txt`；按标题/段落分块；top-k 可配；中文按字符级/双字匹配兜底。该能力以 `IKnowledgeRetriever` 抽象暴露——即「检索后端适配口」；嵌入向量等更强后端留待后续在此接缝后替换实现，调用方（`TraderChatEngine`）不随之改动。

## 备选方案

1. 嵌入向量检索 —— 延后：需 embedding 运行环境与向量存储（SQLite/LiteDB/ONNX），与 v1 的复杂度预算不匹配；接缝已为其预留。
2. 外部 RAG 服务 —— 否决：引入外部依赖、出网与运维成本，违背 v1 自包含目标。

## 后果

- 正面：零额外依赖；可脱离 SPT 运行时用 fixture 文档目录单测（命中/排序/条数上限/空库/中文匹配）；中文可降级匹配；接缝已定，后续可平滑替换为嵌入实现。
- 负面：语义召回弱于嵌入检索——同义/改写的表述可能命中不佳；文档规模增大后准确度与性能受限，需在 M3 随试点文档集评估是否升级为嵌入后端。
