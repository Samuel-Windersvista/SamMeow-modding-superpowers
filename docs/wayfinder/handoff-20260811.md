## Key Breakthrough: Server Migration Pattern Discovered

### AbstractModMetadata → IModMetadata (4.0→4.1 hard break)
Reverse-engineered `SPT.Server.dll` (SPT 4.1.2 ModValidator): 
- 4.0.13 has `AbstractModMetadata` (abstract class); 4.1.0/4.1.2 have `IModMetadata` (interface only)
- ALL 4.0-compiled server mods fail on 4.1.2 with `ReflectionTypeLoadException`
- SptVersion string patching (ldstr ~4.0.0→~4.1.0) is **NOT sufficient** — class reference breakage requires full recompile
- Server-mod-311-to-41.md §7.1-7.10 documents all findings

### 4.1 Database Pattern: Table Model Injection
`DatabaseService.GetTables().Traders` → inject `TradersTable` directly, cast to `Dictionary<MongoId, Trader>`.
`ConfigServer.GetConfig<T>()` → inject config types directly.
(Reference: Croupier 4.1.2 decompilation)

### TS→C# Migration (AKResonant 1850 Pilot)
TS mods using WTTInstanceManager + CustomItemService can be migrated by injecting WTT-ServerCommonLib C# services:
- `CustomItemService` → `WTTCustomItemServiceExtended.CreateCustomItems` (reads db/CustomItems/)
- `CustomAssortSchemeService` → `WTTCustomAssortSchemeService.CreateCustomAssortSchemes` (reads db/CustomAssortSchemes/)
- `CustomWeaponPresets` → `WTTCustomWeaponPresetService.CreateCustomWeaponPresets` (reads db/CustomWeaponPresets/)
- Data files move from `db/Items/` to `db/CustomItems/` (WTT C# convention)
- Bundles from 3114 pack work as-is on 4.1.2 (Unity 2022.3 backward-compatible)
- **Four rounds of fixes needed**: ObjectId validation (names→hex IDs), preset architecture (embedded→independent files), residual empty file cleanup, standard Preset format
