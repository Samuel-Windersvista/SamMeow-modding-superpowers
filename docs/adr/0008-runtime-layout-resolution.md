# 运行时布局解析归一：共享解析器 + env 显式无效即报错 + 插件不设 env

状态：已接受（2026-09-16） | 决策者：Overseer | 范围：spt-MCP / OpenCode 插件 / 便携包打包

## 背景

架构审查候选 C1 的活体实证：OpenCode 插件把 `SPT_KB_ROOT` 计算到仓库上两级的不存在路径，spt-mcp 无条件信任 env 且 `loadJson` 吞错 → KB/Forge 工具呈现「0 条匹配」且无任何报错（比崩溃更糟：失败是静默的）。helper 定位（metadata/IL）存在同类陷阱：env 显式设置即优先、不校验存在性。

候选形态：

- **A 双点最小修复**：修插件路径计算 + spt-mcp 校验 env；不引入共享模块。
- **B 共享运行时布局解析器**：路径解析与逐资源校验归一到唯一模块（无构建纯 ESM，插件与 spt-mcp 双端导入）；插件不再设置 env；env 显式无效即报错（不回退）；便携包与仓库同规则。

判据：唯一计算点、失败可见性、双部署形态（仓库/便携包）一致性、与未来共享内核（mcp-kit）的兼容。

## 决策

采用 **B**。要点：

- `shared/runtime-layout.mjs` 为唯一解析点：返回逐资源报告（path / source / ok / reason），不抛错；`formatLayoutWarnings` 供 stderr 输出。
- env 语义：未设 → 默认派生（包根相对）+ 存在性校验；**显式设置但无效 → 报错，不静默回退**（显式契约不可被悄悄替换）。
- 插件不再设置 `SPT_KB_ROOT` / `SPT_MCP_HELPER` / `SPT_IL_HELPER`；解析权归共享解析器；插件仅在会话启动时输出健康警告（动态导入，模块缺失不炸插件加载）。
- 失败面：spt-mcp 启动写 stderr 警告；KB/Forge 工具在资源不可用时返回结构化错误（`kb_unavailable`）；纯文件系统工具不受影响；新增 `spt_health` 只读工具供 agent 自查。
- 便携包携带知识层（index + curated + wiki，约 5MB；archive 永不进包 → forge 工具显式降级）；helper 产物为打包前置条件（缺失则打包警告 + 打包版降级）。

## 后果

- 知识层故障从静默变响亮：agent 在工具结果即可见错误与修复提示。
- 路径解析单点：插件与 MCP 不再各自计算、不会互相漂移；「插件算出的路径被 MCP 拒绝」类错误面消失。
- 显式 env 无效即报错意味着：配置错误不会被魔法回退掩盖（代价：用户需按 reason 提示修正或移除变量）。
- 便携包与仓库同规则（同一解析器），`mode` 仅为标签。
- 未来 `tools/mcp-kit`（C2 共享内核）可吸收本模块；当前不依赖 C2。
