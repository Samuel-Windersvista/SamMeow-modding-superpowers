# 16: 运行时任务知识注入（态度门控披露）

**What to build:** 商人对话中能正确回答「我名下进行中委托」的细节，且**严禁编造**；披露粒度由态度档位决定（低好感不披露 / 中档只给方向性线索 / 高好感交底）。新增 prompt 段 `{{quests}}`。

**Blocked by:** 14: v2 动态态度（已完成）— 复用 `AttitudeTier` 与关系快照链路。

**Status:** open

## 背景（2026-10-16 实机缺陷取证）

实机中玩家问 Therapist「水瓶座行动」细节，模型**自信编造**：先说地点在「储备站水处理区」（实际是**海关宿舍楼**），被玩家纠正后不但没承认不知道，反而改用「我知道但不说」的姿态补圆（「编号我不背」「带盥洗室那间」「夹克口袋能摸到」）。

- 根因 A（内容缺失）：`knowledge/traders/<id>/` 四篇文档对 钥匙/水瓶/海关/宿舍/任务 的命中数**全为 0**；检索侧 `[kg] 命中数=0`。
- 根因 B（行为失范）：无「不知道就说不知道」约束，模型倾向于编造自洽解释。

## 决策（2026-10-16 grilling，Overseer 全部采纳）

1. **注入范围**：仅该商人名下 **`Started` + `AvailableForFinish`** 的任务详情（名字由 `{{attitude}}` 段负责，详情由本段负责，避免重复）。
2. **披露门控**：`AttitudeTier` → `DisclosureLevel` 三档
   - `Hostile` / `Cold` → **None**（本段不注入详情）
   - `Familiar` → **Hint**（地图名 + 大致区域/目标类型，不给房间号/钥匙名）
   - `Trusted` / `Ally` → **Full**（含具体房间/钥匙名/目标明细）
3. **注入内容与预算**：每任务「任务名 + 目标列表 + 描述截断（≤300 字）」；单任务 ≤500 字、整段 ≤800 字；按顺序丢弃超预算项并告警。**独立于 `{{attitude}}` 的 600 字预算**。
4. **占位符**：新增 `{{quests}}`；旧模板缺该占位符时自动追加（沿用 v2 的兼容做法）；模板同时缺 `{{persona}}`/`{{attitude}}`/`{{quests}}` 时告警。
5. **剧透边界**：Full 档允许报房间号/钥匙名/目标位置——这些文本玩家在游戏内任务面板本就能看到。
6. **反编造硬约束**：`{{quests}}` 段与默认模板均加入「不知道就明说不知道，严禁编造或用『不归我管』之类借口搪塞」。

## 数据来源（exp-2 实证，2026-10-16）

| 需要 | 来源 |
|---|---|
| 玩家进度 | `ProfileHelper.GetPmcProfile(sessionId).Quests`（`List<QuestStatus>`：`QId`/`Status`） |
| 任务静态定义 | `TemplateTable.Quests[qid]`（**运行时已合并 mod 任务**；`TraderId` 用于归属筛选） |
| 任务名 / 描述 | `LocaleService.GetLocaleDb("ch")` → `<qid> name`（小写 n）、`<qid> description` |
| **目标文本** | **裸 24-hex 条件 id 作为独立 locale 键**（无任务前缀）。链路：`Quest.Conditions.AvailableForFinish[]._props.id` → locale[裸键] |

**样例（可作单测 fixture）**
- `59689fbd86f7740d137ebfc4`（水瓶座行动 - 1）→ cond `5a3fb73b86f77458e0324376` = 「在海关找到被藏在宿舍楼里的水」；cond `5968a06486f7740d14064728` = 「以幸存状态撤离该区域」。
- `5968eb3186f7741dde183a4d`（水瓶座行动 - 2）→ cond `5968eb9b86f7741ddb481543` = 「在海关击杀Scav」。

## 测试接缝

1. 披露门控映射：5 档 `AttitudeTier` → 3 档 `DisclosureLevel`（边界全覆盖）。
2. 渲染：Hint 档**不含**房间号/钥匙名；Full 档**含**；None 档不产生任务段。
3. 预算：单任务超 500 字截断并告警；总量超 800 字丢尾并告警；不影响 `{{attitude}}` 段长度。
4. 占位符兼容：旧模板（无 `{{quests}}`）自动追加；单趟替换不二次展开。
5. 反编造约束文本恒存在于 `{{quests}}` 段（含截断路径）。
6. 无任务商人 / 无进行中任务 → 段内容为空且不报错。

## 审查记录（2026-10-16 双轴，@oracle 并行）

**Standards 轴**
- 硬性 1 条：术语漂移——代码注释/文档混用「委托知识」与术语表定义的「**任务知识**」→ 已修订（R5）。
- 判断项 3 条，均裁决**可接受**：渲染层与 v2 评测器的"重复"不构成真重复（一个整段截断、一个逐条+尾丢弃，抽象化会引入投机性泛化）；模板与注入块双写禁令属纵深防御；同批任务名二次解析（≤5 次字典查找）可保留。

**Spec 轴（4 项，其中 1 项击穿验收靶心）**
1. **[CRITICAL] `None` 档与空任务路径下反编造禁令整段消失** —— `RenderQuestBlock` 在 `None`/无任务时返回空串，叠加模板缺「禁止借口搪塞」子句，**实机 Cold 档 prompt 中不含任何反编造指令**，直接击穿本工单的验收靶心（"Cold 档应拒答细节且不编造"）。
   **裁决与解决（R1）**：**反编造禁令恒存**——`{{quests}}` 段在**任何档位、任何任务数下**都以禁令收尾；`None` 档只发"约束行 + 禁令"，不发任何任务内容。
   [WARN] 这**取代**本工单原第 4 条中「`None` → empty section（不注入噪音）」的表述——原始表述与 §测试接缝 5「反编造约束文本恒存在于 `{{quests}}` 段」自相矛盾，本次以"禁令恒存"为准（安全优先）。
2. **默认模板缺「禁止借口搪塞」子句**（README 却声称已含）→ R2 修订，模板补全子句并保持两文件逐字节一致。
3. **Hint 档缺「大致区域/目标类型」维度**、且地区不可解时渲染「未知」→ R3 修订：地区不可解则**省略括号**；补一句不含具体信息的通用引导语。**有意偏离**保留：不实现"目标类型"派生——从目标文本派生类型有泄露具体信息之虞，安全性优先于字面规格（偏离理由记于代码注释与本记录）。
4. **预算诊断失真 + 双重条数上限**：渲染器自持 `MaxQuestsRendered=5` 且条数上限触发的丢弃被误报为「超出总量预算 800 字」；提供器侧 `.Take(5)` 静默截断 → R4 修订：**条数上限单一归属提供器**（与态度段共享的 5，属设计而非意外，已注释说明），渲染器只保留字数预算与**准确**告警文案。
