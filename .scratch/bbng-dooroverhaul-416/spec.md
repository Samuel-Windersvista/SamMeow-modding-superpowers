# DoorBreachOverhaul（破门大修）Spec

> 目标版本线：SPT 4.1.6 / EFT 0.16.9.40743 / Mono / BepInEx 5 / netstandard2.1。
> 部署目标：MO2 实例 "Norvinsk_Forever"（SPT 4.1.6 / profile Default），以覆盖层替换包内 `[8]门的大修-DoorOverhaul`。
> 工程落点：`mods/SamMeow-DoorBreachOverhaul`（SamMeow-modding-superpowers 仓库内；稳定后抽独立仓库）。
> 上游关系：以 BB-NG master（`451c6cb`，MIT）为合并基座，并入 Sage's Door Overhaul v1.0.0（BSD-3）的破坏与交互能力；自持维护、独立演进（hub ADR-0012）。
> 项目档案：研究 `.scratch/bbng-dooroverhaul-416/research.md`；决策 `decisions.md`；术语表与项目 ADR 随工程携带。

Status: ready-for-agent

## Problem Statement

我在 SPT 4.1.6 线上要一套完整的"门"体验，现状被两个 mod 切碎且都不可接受：

- **Backdoor Bandit（BB，破门）**：提供"攻击开门"——枪/近战/爆炸让上锁门与容器打开，用不用钥匙由玩家决定。但 4.1 线没有发布版（上游 master 已完成 4.1 API 迁移但未发版）；且它没有门体破坏视觉。
- **Sage's Door Overhaul（DO，破坏与交互）**：4.1.6 现役，提供门体破坏（弹孔/碎片/铰链/门闩/门板脱落）与门交互（Peek/静开/推门等），但它**刻意忽略对上锁门的攻击**（`locked: untouchable`）——作者用无开关的硬规则替玩家保住了钥匙系统。

核心立场：更多破门方法应由 mod 提供；**是否使用钥匙是玩家的决定，不是作者的决定**。两条能力线需要合并为一个我自持、可独立演进的单 mod，运行在 4.1.6 上，且一切限制由我（玩家/策展人）通过配置决定。

## Solution

交付单一 SPT 4.1.6 客户端 mod：**DoorBreachOverhaul（破门大修）**（assembly `DoorBreachOverhaul`，BepInPlugin GUID `com.sammeow.doorbreach`，版本 0.1.0）。以 BB-NG master 为合并基座，并入 DO 的破坏与交互系统：

- **破门**：射击门锁区域/近战/爆炸打开上锁门与容器（锁血池语义，原生踹门动画）；**上锁门不豁免**（移除 `locked: untouchable`）。
- **破坏**：弹孔/穿透/碎片/铰链/门闩/门板脱落全套并入；与破门**双轨并行**（同一命中同时喂两条线）。
- **门交互**：Peek / Open Further / Open Quietly / 推门 / 踢门持枪全套并入；交互菜单去重合并。
- **排除与开关**：工程性排除可由总开关解除（安全类）；触发任务门/撤离门为高危组子开关（默认关）；物理不可行项保留排除并在调试面板显示原因。
- **配置**：本地 BepInEx（F12）；默认宽松（KeyId 黑名单空、容器/后备箱默认可破、血量与武器白名单沿用上游默认）。
- **C4**：放置式爆炸破门，引爆映射为完整破坏管线；C4 物品/配方由服务端组件提供（独立工单）。

以 MO2 覆盖层部署到 Norvinsk_Forever，替换 DO 覆盖层（目录保留、一键回滚）；BB 在包内未就绪清单中的两项据此收口。双上游 MIT × BSD-3 合规署名。

## User Stories

【破门（Breach）】

1. 作为玩家，我想要用合规武器射击上锁门的门锁区域（门把手附近）把门打开（原生踹门动画），以便不用钥匙也能进门——用不用钥匙由我自己决定
2. 作为玩家，我想要近战武器按配置白名单破门，以便用枪托/斧头等打开门
3. 作为玩家，我想要霰弹枪与榴弹发射器按配置白名单破门，以便保留上游 BB 的武器分类语义
4. 作为玩家，我想要破门命中判定保留上游语义（命中门把手附近才有效；无把手的门任意命中有效），以便手感与上游一致
5. 作为玩家，我想要门锁耐久按区间随机（默认 100–200）且可配，以便调整破门难度
6. 作为玩家，我想要"全放行/半放行"模式开关（Pleb/SemiPleb 类），以便快速切换体验
7. 作为玩家，我想要上锁门对攻击完全不再豁免——射击既有破坏效果、也累积锁损伤，以便"打锁"与"拆门"都能作用于上锁门
8. 作为玩家，我想要射击上锁门时破坏与破门两条线同时生效（双轨语义）、互不阻塞，以便两种进门方式都可行
9. 作为玩家，我想要容器（LootableContainer）与车辆后备箱共用同一破门语义（命中对应锁具锚点），以便用同一手法打开容器
10. 作为玩家，我想要容器与后备箱默认可破（可配置关闭），以便恢复"容器均可枪开"的体验
11. 作为玩家，我想要珍稀房间保护黑名单（KeyId 机制）保留但默认清空，以便限制与否由我决定

【破坏（Destruction）】

12. 作为玩家，我想要射击门板任意位置撕出弹孔（孔洞可视化、碎块掉落），以便看到门的真实损坏
13. 作为玩家，我想要高穿透弹药按材质阈值打穿门板（薄木/厚木/薄金属阈值各自可配），以便穿射门后目标
14. 作为玩家，我想要铰链可被击毁（实验开关）：一门铰链毁则门扇悬挂、全毁则门扇脱落并可通行，以便物理破坏有完整代价链
15. 作为玩家，我想要门闩可被打坏，以便与开门行为形成配合
16. 作为玩家，我想要门板脱落/悬挂后正确阻挡或不阻挡玩家与 bot（可配置），以便物理反馈真实
17. 作为玩家，我想要破坏视觉效果（孔洞、断片、碎片迸溅、玻璃/门芯细节）按 DO 实现完整保留，以便复用成熟视觉质量
18. 作为玩家，我想要破坏系统保留 DO 的调试面板（命中标记、门信息、破坏图谱），以便排查与调参
19. 作为玩家，我想要"安全类"工程性排除（钥匙卡门/滑门/开关门/成对双门/非可操作）可由总开关一键解除，以便我不被作者的设计限制束缚
20. 作为玩家，我想要触发任务门与撤离门作为高危组保留在独立子开关下（默认保持排除、红色警示文案），以便不误伤任务与撤离逻辑；需要时也能打开
21. 作为玩家，我想要物理不可行的门（无弹道碰撞体/无几何/异常尺寸）保留排除并在调试面板显示原因，以便我知道为什么打不坏

【爆炸破门（C4）】

22. 作为玩家，我想要在门上放置 C4（交互菜单项：需持有 C4 物品、门状态与角度合规），以便获得爆炸破门手段
23. 作为玩家，我想要 C4 引爆以完整破坏管线呈现（门扇炸飞/脱落 + 爆炸特效与可选范围伤害），而不是门对象瞬间消失
24. 作为玩家，我想要 C4 的倒计时、蜂鸣音效与计时配置保留，以便计划行动
25. 作为玩家，我想要 C4 对不可破坏的门回退为强制开门，以便 C4 永远有效（上游语义）
26. 作为玩家，我想要 C4 物品与配方由服务端组件提供（独立工单），以便物品体系与客户端主线解耦推进

【门交互与菜单】

27. 作为玩家，我想要 Peek（点按快速开缝 / 按住逐步开到全开）与 Open Further，以便战术观察与渐进开门
28. 作为玩家，我想要 Open Quietly（幅度/缓速/音量可配），以便潜行
29. 作为玩家，我想要身体推门（可配强度）与静音开门的音效控制，以便移动手感自然
30. 作为玩家，我想要踢门时持枪保持就绪/朝向可配，以便踹门不打断战斗准备
31. 作为玩家，我想要交互菜单中破门相关动作（Plant Explosive、Peek、Open Further、Open Quietly 等）合并显示且不重复（去重守卫），以便操作菜单干净
32. 作为玩家，我想要交互菜单与包内其他门类 mod（如门状态随机化）共存不崩，以便包内组合稳定

【配置与默认值】

33. 作为玩家，我想要全部限制都是 F12 旋钮（武器/弹药白名单、材质规则、血量、黑名单、排除开关、高危组开关、破坏参数、交互参数），以便所有限制由我决定
34. 作为玩家，我想要默认值取宽松路线（黑名单空、容器默认开、排除最少限制、血量与武器沿用上游默认），以便开箱即得"更多破门方法"
35. 作为玩家，我想要配置基线覆盖 BB-NG 与 DO 的全部现有旋钮，并以数据驱动结构预留扩展位，以便未来按需加细颗粒度
36. 作为玩家，我想要配置载体为本地 BepInEx（F12、显示名按包惯例中文化），放弃服务端下发，以便配置稳定可靠、始终在手

【健壮、构建与维护】

37. 作为使用者，我想要版本门禁只警告不拒绝加载，以便版本漂移时模组仍可用
38. 作为使用者，我想要单一日志源与统一前缀、进出战局注册/清理闭环、无残留，以便日志可读、反复进出稳定
39. 作为维护者，我想要单一代码库自持（不依赖上游发版节奏；上游更新仅人工对账、择优 cherry-pick），以便独立演进
40. 作为维护者，我想要构建可重复（`dotnet build -c Release`，引用路径参数化、缺失响亮失败），以便环境迁移无痛
41. 作为维护者，我想要 README / LICENSE / THIRD-PARTY-NOTICES 记录双上游署名与偏差表，以便合规与可追溯
42. 作为整合包策展人，我想要以 MO2 覆盖层部署并替换包内 DoorOverhaul 覆盖层（目录保留、一键回滚），以便安全迁移
43. 作为整合包策展人，我想要 BB 未就绪清单项在本 mod 验证通过后据此关闭，以便台账一致

【测试与验证】

44. 作为测试者，我想要规则决策层可单元测试（纯函数：武器/弹药/材质/命中区/门类/配置快照 → 判定结果），以便改动回归有自动化证据
45. 作为测试者，我想要 BepInEx 日志可断言（插件加载、补丁绑定全覆盖、无补丁错误），以便 agent 可独立复验
46. 作为测试者，我想要游戏内验证有固定清单（破门/破坏/C4/交互/开关/排除逐场景），以便人工验证可重复
47. 作为测试者，我想要上游并入的破坏系统不做重写、以集成级验证覆盖，以便风险聚焦在合并接缝而非重造轮子

## Implementation Decisions

- **单插件与补丁面**：一个 BepInPlugin 承载全部补丁与组件；补丁采用 `SPT.Reflection.Patching.ModulePatch` 形态。统一重复补丁点：
  - **命中分派点（唯一）**：以 `BallisticCollider.ApplyHit` postfix 为唯一命中观察入口，同时驱动锁血池与破坏模拟（取代"BB postfix + DO 事件订阅"两套并存形态）。
  - **交互菜单（唯一）**：`InteractionContextHelper.GetAvailableActions` 的 Door 重载合并为单 postfix，追加 DO 全套动作 + Plant Explosive，带动作去重守卫。
  - **战局装配（唯一）**：`GameWorld.OnGameStarted` 单点完成 BB 组件挂载 + DO 注册表/控制器构建；保留 headless/batchmode 守卫。
  - DO 侧守卫补丁（Interact / SetDoorState / KickOpen 接管守卫）、破门视觉交接、爆炸→破坏、遮挡门禁、清理类补丁原样并入；保留 PerfectCulling 防护（门对象可能被销毁或接管）。
- **双轨语义（ADR-0001）**：同一命中同时喂两条线——（a）锁区判定与锁血池（把手锚定、武器/弹药/材质规则、KeyId 黑名单、血量区间）→ 归零触发原生踹门开门；（b）破坏模拟（DO 全套；上锁门豁免移除）。互不阻塞。C4 引爆 → 完整破坏管线（门扇脱落/炸飞）；目标门不可破坏时回退强制开门。
- **排除与开关体系**：DO 的门适用性判定重构为配置化策略层——安全类（钥匙卡门/滑门/开关门/成对双门/非可操作）由**总开关**一键解除；**高危组**（触发任务门/撤离门）独立子开关、默认保持排除、红色警示文案；物理不可行项（无弹道碰撞体/无几何/异常尺寸）不可开关化，调试面板显示原因。KeyId 黑名单默认清空、机制保留。
- **规则层数据驱动**：武器白名单（霰弹/榴弹/近战/其他四类）+ 弹药白名单 + 材质规则 + 命中锚定 + 模式开关（全放行/半放行）+ 血量区间，全部以配置快照为输入、纯函数判定输出——作为唯一单元测试接缝（S0）；配置结构为"按材质/门类/命中区的规则组"预留扩展位。
- **配置面（F12；键名英文、显示名中文）**：节划分 `1.通用` / `2.破门` / `3.破坏` / `4.交互` / `5.爆炸` / `6.排除与开关` / `7.调试`；覆盖 BB-NG 与 DO 全部现有旋钮 + 新增（总开关、高危组子开关）。默认值宽松：黑名单空；容器/后备箱可破；血量 100–200；白名单沿用上游默认。**无配置迁移器**（新 GUID、全新配置面）。
- **身份与版本**：AssemblyName `DoorBreachOverhaul`、GUID `com.sammeow.doorbreach`、显示名 `Door Breach Overhaul（破门大修）`、版本 0.1.0；版本号三处同步（csproj / 插件入口 / README 与覆盖层名）。
- **Fika**：不并入（首期）；保留主插件的无 Fika 依赖桥结构作为未来接入位。
- **服务端组件（独立工单）**：C4 物品/配方/bundle 的 4.1 重建；客户端契约＝物品模板 ID 与 bundle 资源存在；缺席时 C4 菜单项自然不可用、不崩溃。本 spec 不展开其实现。
- **版本门禁**：读 `EscapeFromTarkov.exe` 的 `FilePrivatePart`（40743）；不匹配仅 LogWarning。
- **健壮性**：补丁边界 fail-soft（记录日志 + 功能级降级，不穿透游戏调用链）；内部逻辑保持快失败（不静默 fallback）；单一日志源、统一前缀；进出战局注册/清理闭环。
- **构建**：netstandard2.1；引用本地 SPT 4.1.6（BepInEx\core、Managed、BepInEx\plugins\spt）+ 上游使用到的第三方程序集（WTT-ClientCommonLib、PerfectCulling 等——以触点核验结果为准）；引用根参数化、路径缺失响亮失败；构建产物进 `release/`（包内惯例）。
- **部署**：MO2 覆盖层（`[8]` 分类、包内命名惯例）替换 `[8]门的大修-DoorOverhaul`；同时收口 BB 未就绪两项；meta.ini 写 comments/notes；写入前确保游戏与 MO2 关闭；旧覆盖层目录保留可回滚。
- **上游对账**：BB-NG / DO 更新时人工对账（ADR-0012）；工程 git 历史自合并快照起（不 fork 上游仓库）。
- **产出坐标**：工程 `mods/SamMeow-DoorBreachOverhaul`；spec/工单 `.scratch/bbng-dooroverhaul-416/`；实现期不产生 git 提交（提交由 Overseer 执行）。

## Testing Decisions

- 好测试的标准：只测外部行为（输入 → 判定/可观察结果），不测实现细节；游戏物理与视觉部分以日志断言与游戏内清单验证。
- 接缝（沿用包内三级验证阶梯，新开且仅新开一个单元接缝）：
  - **S0 规则层接缝（新增；本项目唯一新接缝、唯一单元测试点）**：规则层（Attack Policy）为纯函数——输入（武器/弹药模板数据、材质、命中点相对锁锚、门类、门状态、配置快照）→ 输出（锁损伤量、破坏是否受理、拒绝原因）。表驱动单测；受测模块＝规则层；不测补丁装配、不测游戏对象。
  - **S1 构建接缝（agent）**：`dotnet build -c Release` 0 error；包内 mod 标准检查脚本（client / 4.1.6，如适用）通过。
  - **S2 加载接缝（Level B；Overseer 启动、agent 断言）**：经 MO2 启动至主菜单；agent 读 BepInEx 日志断言：插件加载行、补丁绑定全覆盖、无 `Failed to create patch`、无异常。
  - **S3 功能接缝（Level C；Overseer 执行、agent 提供清单与日志复验）**：破门（上锁门射击→开门；近战；容器/后备箱）；破坏（弹孔/穿透/铰链实验开关/门板脱落）；C4 全流程；交互全套；总开关与高危组开关行为；调试面板；与门状态随机化的菜单共存。
  - **S4 辅助接缝（可选）**：tarkov-runtime bridge 运行时读数作旁证（不依赖、不阻塞）。
- 受测对象：规则层（单元）+ 整插件（集成级）。上游并入的破坏系统不做重写、不做单元测试，以集成验证覆盖。
- Prior art：`spt41-debugtoolkit` 的 Level B/C 流程与断言方式；`mods/InescapableTarkovsSoftcore416/tests` 的测试工程形态；包内 STD-VERIFY 系列规则。

## Out of Scope

- Fika / 多人同步。
- SPT 5.0 线（IL2CPP）及跨线代码共享。
- 上游自动同步 / 自动 rebase（仅人工对账）。
- DO 破坏算法与视觉的重做（原样并入后再演进）。
- 破门弹物品复活（上游 2.0.0 已移除的死分支）。
